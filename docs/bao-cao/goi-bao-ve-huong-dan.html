Đề tài: Ứng dụng Vision-Language Model trong Kiểm thử Tự động Giao diện Người dùng Phần mềm

Sinh viên: [Họ tên — MSSV]  ·  GVHD: [Họ tên GVHD]  ·  UIT — ĐHQG TP.HCM, 2026

Tài liệu này dành cho người chưa từng tham gia đồ án: đọc mục 1–2 để hiểu gói gồm gì; làm theo mục 3–6 để tự chạy được toàn bộ demo trên máy bất kỳ.

1. Đồ án này làm gì? (tóm tắt 30 giây)

Đồ án so sánh định lượng hai cách kiểm thử giao diện web tự động trên cùng một ứng dụng mẫu và cùng 18 kịch bản kiểm thử:

  • Cách truyền thống (locator): script Playwright định vị phần tử bằng CSS/XPath — chạy rất nhanh nhưng gãy hàng loạt khi giao diện đổi cách trình bày.
  • Cách mới (VLM): test viết bằng ngôn ngữ tự nhiên, mô hình thị giác-ngôn ngữ (Qwen3-VL qua Midscene.js) "nhìn" ảnh chụp màn hình để thao tác — không gãy khi giao diện đổi, đổi lại chậm hơn và tốn phí API (~$0.05/lượt chạy).

Ứng dụng mẫu "Mini Shop Manager" có 4 biến thể giao diện (V0 gốc, V1 đổi màu, V2 đảo bố cục, V3 đổi nhãn/icon) để đo độ bền vững; kèm hai khảo sát mở rộng về kiểm thử phân quyền hiển thị và che dữ liệu nhạy cảm trước khi gửi ảnh lên API.

3. Chuẩn bị môi trường (một lần, ~15 phút, cần mạng)

1Cài Node.js (phiên bản 20 trở lên) — môi trường chạy JavaScript:
  • Cách đơn giản nhất: vào https://nodejs.org, tải bản LTS, cài như phần mềm thường.
  • Kiểm tra đã cài xong: mở Terminal (macOS: Spotlight gõ "Terminal"; Windows: Start gõ "PowerShell") và chạy:
node --version

Thấy in ra v20.x trở lên là đạt.

2Giải nén mã nguồn. Nhấp đúp 05-ma-nguon/doanai-src.zip (hoặc chạy lệnh dưới). Kết quả: thư mục doanai-src. 
cd 05-ma-nguon
unzip doanai-src.zip

Mọi lệnh từ đây trở đi chạy bên trong doanai-src. Gõ cd doanai-src để vào.

3Cài thư viện cho từng phần — dự án gồm 3 phần độc lập, phải cài trong từng thư mục con (chạy npm install ở gốc sẽ báo lỗi "no package.json"): 
# Đang đứng ở thư mục doanai-src

cd app
npm install
cd ..

cd tests-locator
npm install
npx playwright install chromium
cd ..

cd tests-vlm
npm install
cd ..

Lệnh npx playwright install chromium tải trình duyệt Chromium riêng cho việc chạy test (~150 MB).

4Kiểm tra môi trường — chạy bộ test truyền thống, không cần API key: 
cd tests-locator
npx playwright test

Sau ~40 giây phải thấy 30 passed (bộ test tự khởi động ứng dụng, không cần mở gì trước). Thấy dòng này nghĩa là môi trường đã sẵn sàng.

4. Mở ứng dụng mẫu (xem bằng mắt)

5Chạy ứng dụng: 
cd app
npm run dev

Terminal in ra địa chỉ — mở trình duyệt vào http://localhost:5173, đăng nhập:

  • admin / admin123 — thấy đủ: nút xóa, cột Cost, trang Settings.
  • staff / staff123 — bị ẩn các phần trên (phục vụ kiểm thử phân quyền).

Xem 4 biến thể giao diện (cùng chức năng, khác trình bày) bằng cách thêm tham số vào địa chỉ:

http://localhost:5173/products?variant=v0   ← gốc
http://localhost:5173/products?variant=v1   ← đổi màu (dark)
http://localhost:5173/products?variant=v2   ← đảo bố cục/cột
http://localhost:5173/products?variant=v3   ← đổi nhãn nút/icon

Dữ liệu hoàn toàn giả lập trong trình duyệt — không có server/database thật. Muốn tắt app: bấm Ctrl+C trong Terminal.

5. Demo "test truyền thống gãy khi giao diện đổi" (không cần mạng)

6Chạy 18 test truyền thống trên biến thể V2 (giao diện bị đảo bố cục): 
cd tests-locator

# macOS / Linux:
APP_VARIANT=v2 npx playwright test tests/group-a-forms.spec.ts tests/group-b-list-search.spec.ts tests/group-c-crud.spec.ts tests/group-d-custom-widgets.spec.ts --reporter=line

# Windows PowerShell (2 lệnh):
$env:APP_VARIANT="v2"
npx playwright test tests/group-a-forms.spec.ts tests/group-b-list-search.spec.ts tests/group-c-crud.spec.ts tests/group-d-custom-widgets.spec.ts --reporter=line

Sau ~45 giây thấy 9 failed / 9 passed — một nửa bộ test gãy chỉ vì giao diện đổi cách trình bày. Đây chính là số liệu RQ1 trong báo cáo (Hình 4.1).

7Đối chứng phía VLM — mở report offline: nhấp đúp 04-demo-offline/vlm-suite-report.html. Chọn một test bất kỳ (ví dụ A3) để xem: câu lệnh ngôn ngữ tự nhiên → ảnh màn hình AI "nhìn" → vị trí nó bấm. Bộ test này đạt 18/18 trên cả 4 biến thể mà không sửa dòng nào — vì nó mô tả ý định thay vì cấu trúc kỹ thuật.

6. (Tùy chọn) Chạy test VLM "sống" — cần mạng + API key

Bước này gọi mô hình AI thật qua mạng, tốn phí rất nhỏ (<$0.01/test). Chỉ cần khi muốn chứng minh hệ thống chạy thật trước hội đồng; nếu không, report offline ở mục 5 đã đủ bằng chứng.
8Tạo file cấu hình key: 
cd tests-vlm
cp .env.example .env        # Windows: copy .env.example .env

Mở file .env vừa tạo bằng editor bất kỳ, điền key OpenRouter (lấy tại openrouter.ai → Keys → Create Key; tài khoản cần nạp credit tối thiểu) vào đúng một dòng:

MIDSCENE_MODEL_API_KEY=sk-or-v1-xxxxxxxx

Các dòng khác giữ nguyên (model đã ghim, temperature 0). Không chia sẻ file này cho ai.

9Chạy 1 test VLM ngắn nhất: 
cd tests-vlm
npx playwright test tests/group-a-forms.spec.ts -g "A2"

Sau ~40–90 giây thấy 1 passed. Nhật ký chi tiết (kèm ảnh từng bước) tự sinh trong tests-vlm/midscene_run/report/ — mở file HTML mới nhất bằng trình duyệt.

8. Tính tái lập của số liệu

Mọi hình và bảng trong báo cáo sinh lại được từ dữ liệu thô đã kèm trong gói: sau khi cài Python 3 + matplotlib (pip install matplotlib), chạy tại thư mục doanai-src:

python3 harness/make-figures.py

Kết quả xuất ra results/figures/ và results/analysis-summary.md — đối chiếu được với 03-so-lieu-hinh/ trong gói. Mã nguồn đầy đủ cũng được công khai tại https://github.com/[TAI-KHOAN-GITHUB]/doanai.

Gói được sinh tự động từ mã nguồn đồ án (script harness/make-defense-package.sh). Mọi thắc mắc về nội dung: xem báo cáo 01-bao-cao/bao-cao-doan.docx, đặc biệt Chương 3 (phương pháp) và Phụ lục A (tái lập).
